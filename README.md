**Лозинський Р. Р., КБ-202, варіант 13**

Виконано обидві частини методички: класичні HTML/CSS/JavaScript та React з хуками.

## Запуск

Потрібен Node.js 20.19+ або 22.12+ (Vite 7) та npm.

```sh
npm install
npm run dev
```

Відкрити адресу, яку виведе Vite (типово http://127.0.0.1:5173/).

- `/` — звичайний JavaScript.
- `/lab_2_react/` — React.

Перехід між версіями є в навігації. Через `file://` файли запускати не слід: застосовано ES-модулі.

```sh
npm test
npm run build
npm run preview
```

`dist/` містить готову збірку, яку можна віддавати статичним HTTP-сервером.

## Реалізовані завдання

1. `navigator`, `screen`, часовий пояс записуються як JSON у `localStorage` під ключем `lab4.system`. У футері можна розгорнути всі записи сховища. Інформація доступна в межах дозволів браузера; точна версія ОС може бути прихованою.
2. Відгуки завантажуються з `https://jsonplaceholder.typicode.com/posts/13/comments` у початковому порядку (61–65). Є стани завантаження, порожнього результату та помилки з повторним запитом.
3. Модальна форма автоматично відкривається через 60000 мс. Її також можна відкрити кнопкою. Після першого показу вона не відкривається автоматично повторно в цій вкладці, зокрема після оновлення або переходу до іншої версії. Стан зберігається в `sessionStorage`.
4. Світла тема діє з 07:00 до 20:59:59 за локальним часом користувача, темна — решту доби. Перевірка часу відбувається щосекунди. Ручний вибір діє до натискання «Авто» або перезавантаження.
5. Поля форми: ім’я, email, телефон, повідомлення. Використано наданий endpoint `https://formspree.io/f/xrppolyg` (спільний `config.js`). Після POST показується результат; при помилці введені дані зберігаються.

## Перевірки та межі

Модульні перевірки: межі теми, адреса й порядок API, помилки HTTP, сховище, перевірка адреси Formspree та POST.

Браузерні перевірки: обидві версії, реальний JSONPlaceholder, модальне вікно рівно через 60 с (керований годинник), збереження стану показу, ручні теми, ширина 390 px, успіх і помилка форми з підміною відповіді Formspree. Фактичний лист не надсилався; отримання листа потрібно перевірити вручну у власній скриньці після надсилання форми.

У робочій папці є `tmp/browser-qa.cjs` з автоматизованою браузерною перевіркою. Для переносимого запуску потрібно налаштувати шлях до Playwright і Chrome; до архіву для здачі тимчасові матеріали не входять.
